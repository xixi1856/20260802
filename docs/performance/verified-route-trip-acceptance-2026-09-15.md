# 已核验路线风险与行程轨迹短时验收（2026-09-15）

## 结论

本轮在 10 km × 10 km 区域内使用 300 条问题完成短时非功能验收。路线风险、轨迹写入、行程历史与轨迹读取均满足既定延迟、错误率和零丢弃门槛。按要求未执行持续运行测试，树莓派端因暂无设备未测试，高德候选路线端到端测试因本机未配置 `AMAP_WEB_KEY` 未执行。

## 投票与日志链路

- 通过真实 API 依次提交 2 票 LOW、2 票 HIGH，最终结果为 `HIGH` 且状态为 `VERIFIED`，符合高等级优先的平票规则。
- Kafka 日志主题为 6 分区、3 副本，测试时所有分区 ISR 均为 3。
- 完整链路“日志卷 → Fluent Bit → Kafka → 消费者 → PostgreSQL”已通过。ERROR 日志成功归档，`password` 和精确坐标被替换；INFO 日志归档数为 0。
- 测试发现并修复日志主题未声明、Fluent Bit JSON parser 未显式注册、Kafka 输出额外时间戳破坏严格事件契约三个问题。

## 自动化检查与限制

- `mvn verify` 通过：72 个单元/架构测试和 5 个 Testcontainers 集成测试，0 失败、0 跳过；9 个 Flyway 迁移在全新 PostGIS 中执行成功。
- 首次报告因命令行 `-DargLine` 覆盖 JaCoCo agent 参数而错误复用了旧数据；保留 JaCoCo 参数重新执行后，仓库当前行覆盖率为 57.14%、分支覆盖率为 39.15%，仍低于 `AGENTS.md` 的 70% 总体目标。Maven 尚未配置覆盖率门禁，因此构建通过不代表覆盖目标通过；应补充高德适配器、核心服务异常分支和 Web 安全边界测试，并启用 JaCoCo check。
- Docker Compose 原 MinIO Docker Hub 地址无法拉取，已改为同版本 Quay 官方镜像并完成启动验证。
- 结果文件保存在忽略提交的 `load/results/`。本轮为同机、短时回归数据，不能外推为生产 SLA，也不能与旧的 10,000 条高密度数据直接计算性能提升比例。

## 简历量化表述建议

- 将步行导航能力从单一路线提升为最多 3 条候选路线，采用 GCJ-02/WGS84 转换、PostGIS 分段走廊检索和问题 ID 去重，并按高/中/低风险数与长度排序；路线风险评估接口在 10 km、300 条风险问题基线下支撑 30 RPS，p95 13.55 ms、p99 22.73 ms、错误率 0。
- 提升行程轨迹的可追溯性，新增带所有权校验的历史、详情和时间游标轨迹接口，并支持手机批量补点后结束行程；20 RPS、每批 20 点时写入 p95 16.60 ms，三类读取接口 p95 均低于 19 ms，测试累计写入 12,020 点且无丢失。
- 提升众包风险判定与日志审计可靠性，引入确认票风险等级聚合及“平票取高”等级规则，并建设 Fluent Bit→3 副本 Kafka→PostgreSQL 的独立日志归档链路；真实 API 验证 2:2 平票稳定选择 HIGH，端到端验证 WARN/ERROR 归档、INFO 丢弃及凭据/精确坐标脱敏。
